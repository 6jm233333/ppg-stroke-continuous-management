# Documentation index

This documentation is organized around scientific reproducibility rather than software marketing.

## Core documents

| Document | Purpose |
|---|---|
| `METHODS_OVERVIEW.md` | End-to-end study design and modelling workflow. |
| `REPRODUCIBILITY.md` | Required inputs, execution levels, and validation safeguards. |
| `DATA_ACCESS.md` | Source-dataset restrictions, privacy boundaries, and expected local data layout. |
| `MODEL_CARD.md` | Intended use, training design, evaluation, risks, and non-use cases. |
| `SOURCE_CODE_PROVENANCE.md` | Mapping from cleaned release modules to the real project scripts. |
| `NEGATIVE_CONTROLS.md` | Diagnostic falsification analyses and interpretation boundaries. |
| `PPG_FEATURES.md` | PPG morphology feature families and documentation requirements. |
| `RESULTS_REPORTING.md` | Standard reporting rules for metrics, tables, figures, and uncertainty. |
| `MANUSCRIPT_ALIGNMENT.md` | Approved wording and phrases to avoid. |
| `PROJECT_STRUCTURE.md` | Expected repository layout and file ownership. |
| `ENVIRONMENT.md` | Environment-management recommendations. |
| `SECURITY_AND_PRIVACY.md` | PHI, restricted data, and release safeguards. |
| `RELEASE_CHECKLIST.md` | Pre-publication checklist for a GitHub/Zenodo release. |

## Review priority

Before public release, review in this order:

1. `SECURITY_AND_PRIVACY.md`
2. `DATA_ACCESS.md`
3. `MANUSCRIPT_ALIGNMENT.md`
4. `REPRODUCIBILITY.md`
5. `RELEASE_CHECKLIST.md`
